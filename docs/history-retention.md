# Historical search and alert history

Apply additive migration 0018_history.sql before deploying the corresponding Worker, after independent review and backup. Do not rerun initial schema or seeds. No production migration or mail is part of this change. The migration restores missing current article copies from each URL's latest archived revision, preserving publication and first-seen dates; existing copies win. Existing FTS triggers index restored text. This can be a substantial one-time write; assess database size and migration time before production. It also creates date/source indexes and delivery-history triggers. Reverting the Worker would resume deletion of current copies, though permanent archive revisions remain.

Search defaults to all retained current copies, newest publication date first, with URL tie-breaking, optional last-14-days and source filters. Pagination retains the existing 50-page bound. FTS searches stored headlines/excerpts and matching translations; the existing LIKE fallback remains available if FTS fails. Revision browsing remains separate. No full-page crawling or Wayback import occurs. Recent feeds and translation queues retain their existing date limits. Existing alert activation and first-seen watermarks remain unchanged: restoring historical copies does not activate historical notifications.

Delivery history starts with new queue insertions after migration. It stores internal account ID, article canonical URL key, normalized matched phrases, queue/update timestamps, outbox ID, attempts and state. It never copies bodies, addresses, capability tokens, provider references or errors. “provider_accepted” means API/log acceptance, never inbox delivery. Pending, sending, uncertain, unresolved, failed, cancelled and expired retain their distinct meanings. State changes follow outbox updates atomically through triggers; pruning preserves unresolved ambiguity and marks unsent work expired. Existing retry rules are unchanged. History expires 90 days after queue insertion during alert sweeps; account closure deletes its history immediately. The sensitive outbox still expires after 1–2 days.

No historical delivery success is backfilled. Legacy alert_notified means enqueue deduplication, not sending or acceptance; already-pruned outboxes cannot be reconstructed. Existing queued/outbox rows at migration time do not gain retrospective history. Phrase matching may reveal sensitive interests, so history remains internal and is removed at unsubscribe. The canonical URL is the existing internal article key, not a copied article body.

Production preflight (November 22): the read-only latest-revision query found 13 missing current copies with 4,264 characters of payload/translation text; D1 reported 30,756,864 bytes total database size. This is a small restoration, but index/trigger storage overhead is additional. Measure local migration and verify the count again immediately before application.
